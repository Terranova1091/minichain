# ADR 0001: Нечётный узел в дереве Меркла

Статус: принято. Дата: 2026-11-01

## Контекст
При построении дерева Меркла над списком транзакций необходимо принять решение по следующей проблеме: что делать, когда на каком-то из уровней дерева нечётное число узлов.

## Решение
Принято: нечётный последний узел переходит на следующий уровень без изменений. Лист хешируется с префиксом 0x00, узел с префиксом 0x01, во всех случаях используется двойной SHA-256:
- хеш листа = sha256d(0x00 ‖ байты транзакции);
- хеш узла = sha256d(0x01 ‖ левый хеш ‖ правый хеш).

Один лист даёт корень, равный хешу этого листа. Пустой список транзакций недопустим.

## Альтернативы
Рассмотрено решение, принятое в сети Bitcoin: дублирование последнего узла. От него решено отказаться, так как оно даёт одинаковый корень для разных наборов транзакций. Например, набор [a, b, c] дополняется до [a, b, c, c], поэтому корни [a, b, c] и [a, b, c, c] совпадают, и два разных набора неразличимы по корню.

## Префиксы
Префикс 0x00 у листа и 0x01 у узла нужен, чтобы хеш листа нельзя было выдать за хеш узла: без префиксов 64 байта, хеш которых равен хешу внутреннего узла, можно было бы предъявить как «транзакцию» и подделать дерево.

## Последствия
Принятое решение устраняет коллизию корня при нечётном числе листьев. С другой стороны:
- в доказательстве включения для узла, перешедшего наверх без пары, на этом уровне нет соседа, поэтому такой уровень пропускается, и verify_proof должна уметь это обрабатывать;
- корни не совпадают с корнями блоков Bitcoin, поэтому сверка с реальными блоками Bitcoin невозможна.
