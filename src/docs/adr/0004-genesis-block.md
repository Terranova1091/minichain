# ADR 0004: Генезис-блок как детерминированная функция от `bits`

- Статус: принято
- Дата: 2026-11-04
- Связано: ADR 0002 (PoW), ADR 0003 (пересчёт сложности)

## Контекст

Каждый блок ссылается на предыдущий через `prev_hash`. У первого блока (генезиса)
предыдущего нет, поэтому он строится особым образом. Генезис выполняет три роли:

1. начало цепи: с него начинаются отсчёт высоты и проигрывание состояния;
2. идентификатор цепи: два узла в одной сети имеют один и тот же генезис
   (в J4 хэш генезиса проверяется при рукопожатии);
3. защита от подмены начала: валидатор отвергает цепь с неожиданным генезисом.

ТЗ содержит два требования, которые на первый взгляд противоречат друг другу:

- `Chain::validate()` проверяет, что генезис «совпадает с зашитым в код»;
- команда `minichain init --bits N` создаёт цепь с заданной начальной сложностью.

Блок генезиса зависит от `bits` (поле заголовка и, как следствие, `nonce` и хэш),
поэтому один готовый блок зашить нельзя.

## Решение

### 1. Генезис задаётся правилом, а не готовым блоком

Генезис это детерминированная функция `genesis(bits) -> Result<Block, GenesisError>`.
Все поля, кроме `bits`, фиксированы константами в коде. Майнинг детерминирован
(перебор `nonce` с нуля, ADR 0002), поэтому для одинаковых `bits` результат всегда один и тот же.

Выражение «зашито в код» означает: зашиты константы и правило построения.

### 2. Валидация генезиса

Валидатор цепи берёт `bits` из заголовка первого блока, строит `genesis(bits)` заново
и требует побайтового равенства с блоком из файла (`==` для `Block`). Если `bits`
первого блока вне допустимого диапазона, цепь отвергается.

Начальная сложность при этом не защищена от выбора создателем цепи (параметр `init --bits`):
это параметр сети, а не защитный механизм. Начиная с блока 1, `bits` проверяется по правилу
пересчёта (ADR 0003).

### 3. Ошибки

`GenesisError` содержит `InvalidBits`, `Block(BlockError)`, `Mine(MineError)`, с реализациями
`From` для `?`. Ошибки блока и майнинга не должны возникать при допустимых `bits`;
они сохранены, чтобы не использовать `unwrap`.

## Последствия

Плюсы:
- один механизм покрывает и `init --bits N`, и проверку «генезис совпадает с ожидаемым»;
- тестируется как чистая функция, результат независим от окружения, запуска и времени;
- хэш генезиса можно использовать как идентификатор цепи в будущей сети (J4).

Минусы:
- изменение любой константы (дата, адрес, награда, `BLOCK_VERSION`) или формата кодирования
  меняет генезис, а значит делает несовместимыми все ранее сохранённые цепи.
  Тест с известными значениями (см. ниже) должен упасть при любом таком изменении;
- у цепей с разными начальными `bits` разные генезисы, то есть это разные сети.
  Для учебного проекта это принято сознательно;
- майнинг генезиса при каждом `init` и при каждой валидации занимает время `~2^bits` попыток.
  Для `bits <= 20` это секунды, для тестов используется не больше 12.

## Рассмотренные альтернативы

1. **Готовый блок, зашитый в код целиком.** Не работает с параметром `--bits`.
   Пришлось бы зашить по блоку на каждое значение либо ограничить сложность одним значением.
2. **Генезис с текущим временем и случайным адресом.** Разные узлы получили бы разные цепи.
3. **Хэш генезиса как единственная зашитая константа.** Подходит для реальных сетей с одним
   значением сложности. Здесь потребовал бы по константе на каждое `bits`.
4. **Генезис без транзакций.** Противоречит ТЗ (пустой список транзакций недопустим, ADR 0001)
   и усложнил бы правило «в блоке ровно одна coinbase».

## Тесты, фиксирующие решение

- Детерминизм: `genesis(8)` дважды даёт равные блоки.
- Поля: `height == 0`, нулевой `prev_hash`, `timestamp == GENESIS_TIMESTAMP`, одна coinbase с
  ожидаемыми полями.
- Корректность: `verify_merkle_root()` возвращает `Ok`, `meets_target()` истинно, `nonce` наименьший.
- Недопустимые `bits` (0, 256, `u32::MAX`) дают `InvalidBits` без майнинга.
- Сборка заголовка и транзакции вручную байт за байтом совпадает с результатом `genesis`.
- Известные значения (`bits` 1, 8, 12): `nonce` 1, 358, 1072 и соответствующие хэши.
  Значения посчитаны независимо от кода (Python, hashlib).
